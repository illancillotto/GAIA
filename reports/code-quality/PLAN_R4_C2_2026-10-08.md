### Concrete simplification

1. A typed, pure resolver projection receives `GisResolveRefsResponse` and
   returns geometry-preserving GeoJSON, selection items and `ImportStats`.
   This removes primitive nullish/source-row mapping from orchestration but
   **does not by itself count as debt reduction**.
2. A pure feedback selector uses guard clauses for zero found and zero geometry,
   then the original positive anomaly-sum condition. Three repetitive
   not-found/multiple/invalid message branches become an explicit ordered
   domain-fragment table, retaining only positive fragments. This is actual
   deduplication and removal of nested reasoning, not relocating the same if tree.
3. The page applies returned feedback only when present, preserving error/info
   selection. Do not unconditionally clear both channels after a completed
   import: concurrent workflows may have changed them since the initial clear.
4. Projection runs before the existing counter increment. Layer metadata stays
   a local literal; append/focus stays before feedback computation/application.
   No wrapper solely to shorten the remaining literal or LOC.

Prefer two small pure functions plus genuinely necessary row/fragment callbacks,
not one 74-line import helper. Every new callable must stay below error thresholds,
ideally below all warning thresholds; metrics across all introduced code decide.

## Behavioral invariants

- Token guard, busytrue, initial error/info clear, file read, first worksheet,
 5000-row normalization, resolver token/options and catch/finally unchanged.
- Statistics use backend counters as supplied. Geometry count alone uses
  `geometry != null`; do not drop geometry-null features from layer GeoJSON.
- Selection items include only exact `FOUND` with truthy particella_id; preserve
  input order, duplicates, row_index0, nullish index→null and original source_ref
  fields. Never infer/correct ids, deduplicate rows or derive found from items.
- Preserve the original FeatureCollection object when present; null/undefined
  gets the same empty collection. No geometry transformation or mutation.
- Counter increments after successful projection, even for zero-found imports.
  Same draft-id/color cycling and filename suffix removal. Do not reserve ids
  before the network response or stop zero-found imports before layer append.
- Every resolved import appends a draft and attempts focus before feedback;
  empty GeoJSON produces no focus/resize increment through the existing guard.
- Feedback precedence: found===0 error; else withGeometry===0 error; else
  positive not_found+multiple+invalid sum emits info; otherwise no new feedback.
  Do not change exact predicates, clamp inconsistent counters or invent success.
- Partial info text/order/spaces remain: prefix, Non trovate, Multiple,
  Righe invalide. Preserve both the sum condition and each positive fragment.
- React dependencies, effects, races and closure behavior unchanged. No new
  await, state reducer, abort/cancellation, API call or timing correction.
- Persisted draft payload remains the same items/stats/source filename; archive
  mutations and MapContainer production internals are outside proposed ownership.

## Risks and stop conditions

- A naive early return would skip no-found draft creation and change color/id
  allocation. A premature counter increment would consume an id on failed
  projection. These are functional changes, not acceptable simplifications.
- A generic feedback object applied through two unconditional setters changes
  concurrent state semantics. Domain values are allowed; setters remain page owned.
- Building feedback before append/focus can reorder evaluation/side effects;
  keep phases at original locations, even though data transformations are pure.
- A reduce that deduplicates/filter-removes features or renumbers source rows
  alters persistence and cannot be justified by lower metrics.
- Existing page unit tests mock the map/API boundaries. Their100% does not
  certify native GIS lifecycle, map tile access or live PostGIS behavior.
- If AST aggregates do not decrease, matching is ambiguous, a new unexplained
  failure appears or equivalence needs shared-hook/archive changes: STOP.
