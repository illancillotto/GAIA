## Responsibility and meaningful simplification

The model builds monthly record insights, not a React/context mega-hook.
`buildMonthlyRecordInsights(records, readRecordFacts)` consumes the records and
one pure projection of six domain facts: ordinary, extra, absence, Saturday,
cell kind and schedule. Existing domain calculations/classification remain in
the page, unchanged. The projection receives no setters, API client, state,
permissions, editor, modal context or lifecycle controls.

Real duplication removed:

- Extra, KM and travel are normalized once per record and added with one
  common accumulator to collaborator, day and month-summary targets. This
  replaces three copies of operational arithmetic and repeated nullish
  decisions without reassociating sums.
- Daily request/anomaly registration uses one ordered descriptor loop, rather
  than duplicate set creation/add/store blocks. Counts still increment for
  each record while the sets retain distinct collaborators.
- Collaborator details and schedule distributions have their own small
  accumulator responsibilities. Dominant-schedule selection is isolated from
  record accumulation; no helper receives the original 69-cognitive callback.
- Type definitions move to their actual model owner. This relocation alone
  has no independent complexity-reduction claim.

## Equivalence and invariants

- Each accumulator observes records in source order. Floating-point additions
  remain left-to-right for each numeric field, including negative values,
  explicit zero, NaN and nullish defaults; no `||` fallback, coercion of
  numeric fields, clamping or aggregate reassociation is introduced.
- Effective extra/ordinary and absence calculation helpers are unchanged.
  Effective overtime retains precedence over raw overtime, even for zero and
  NaN. Availability retains `none => 0`, otherwise `quantity ?? 1`.
- Monthly collaborator and global anomaly counts include only `anomaly`.
  Daily attention counts and collaborator sets include both `anomaly` and
  `analysis`. Requests retain detail-request OR description semantics.
- Duplicate records increment record counts but do not duplicate set members.
  Map/Set insertion order, absent-day maps and present IDs are preserved.
- Absence causes sum in insertion order. Saturday entries retain arrival
  order and duplicates; the existing UI owns chronological sorting.
- Schedule counts retain source and Map insertion order. Strict `>` chooses
  the first encountered code on frequency ties. Labels remain global by
  code, retain the first truthy label and otherwise fall back to the code.
- Saturday ordinal is evaluated only for truthy Saturday labels. Schedule
  label is evaluated only when a truthy code exists. Its unchanged reader is
  a property/nullish-only function, unable to throw on schema-valid records;
  projecting the same label for an already-known code adds no side effect and
  does not overwrite the first global label.
- Input records and nested source data are not mutated; each call builds new
  maps, sets, arrays and accumulator objects. Projection facts are not source
  record objects.
- All React state, hook ordering, effects, memo dependencies, deferred search,
  API/cache calls, polling, cleanup, permissions, editor and UI are unchanged.
  Diff review and an exact comparison of the 20 single-line memo/effect
  dependency arrays confirm equality. The recordInsights memo still depends
  on `[records]`; no JSX is changed.
