  busy/testing/dialog changes and protected API calls, as before.
- Create for null id; update for numeric id including0. Label and login/username
  trim; create password is raw, update whitespace-only password is undefined,
  otherwise replacement password remains raw. Remember/active/hour fields stay.
- Pure save dispatch returns the **original API promise**, not an async wrapper;
  API calls remain synchronous until the original await, including throws.
  Form data is not mutated. No new microtask is introduced by an extra await.
- Save order: busytrue → request → status → await reload → reset → errornull →
  finallybusyfalse. Reload intentionally catches its own errors; failed reload
  does not turn a successful mutation into a failure and save still clears it.
- Delete success flow, selected-form reset condition, error/status ordering and
  final busyfalse remain unchanged. No new shared lock or concurrency guard.
- Bonifica test awaits reload before feedback; Error and ApiError502 preserve
  the same message, non-Error gets the same fallback. Removed502 special branch
  was redundant because ApiError already extends Error.
- Capacitas result uses the success flag read after reload. Success/failure
  feedback setter order remains; one common functional dialog updater retains
  current credential/start/open values, computes finishedAt **inside** updater
  and keeps HTTP200/token/null/detail/diagnosis semantics.
- Closing a running dialog does not reopen it when the result arrives. Error
  diagnostics are still built before feedback; failure diagnosis itself remains
  in the functional updater. No eager calls on other tabs or unrelated render.
- All effects and dependencies unchanged; no API/auth/schema/permission change.
